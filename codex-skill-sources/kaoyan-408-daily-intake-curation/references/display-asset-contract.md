# 408 stable display asset contract

The complete conversation package is temporary local evidence and later a T9 raw
archive. Its filesystem paths are never formal display paths.

Before sealing a canonical `new|redo` package, reopen the exact manifest and include
one canonical `cs408-display-asset-plan-v1`. Classify every attachment. The writer,
not Sol, derives all destinations under
`kaoyan-408-details/assets/<FORMAL_ID>/`. It fully validates promoted PNG/JPEG/WebP,
reuses only identical existing bytes, and fails rather than overwriting a conflict.

The same RepoLock/WAL transaction publishes the stable assets, a package-scoped
managed embed block, and `cs408-obsidian-asset-closure-receipt-v1`. Both new and redo
must use this route. Existing details prose and old embeds remain untouched.

Postcommit must reread the card, assets and embeds. Before any local heavy-byte
cleanup, the archiver repeats that verification and scans the formal repo/details
vault for package, inbox or absolute T9 image references. Closure failure is
`FORMAL_COMMITTED_ARCHIVE_PENDING` with `pending_component=display_assets`; preserve
the local package and never replay formal apply.
