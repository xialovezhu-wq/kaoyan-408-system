# 408 晚间复盘

本机路径和解释器先按[共享路径约定](../_shared/kaoyan-408/local-paths.md)定位；下文仓库命令在已定位的项目目录执行，历史回执保留原字节。

## 按请求选择交付

- 用户要“睡前资料、今晚看的复盘、知识点总结、速记”时，默认生成下述独立知识卡。沿当前上下文理解“复盘”，不把阅读资料请求改成问答。
- 用户要求“提问、测验、主动回忆、逐题问答”时，使用后文问答流程；已开始的问答按原进度继续。
- 真实首答、提示依赖和个人概况用于内部选择知识点与讲解重点，不写成睡前资料中对用户学习表现的概括。

## 当日正式入库后的全天交互阅读

按[全天交互 HTML](references/daily-reading.md)使用原生 `local-context` 取得当天完整材料、本机收尾凭据及同版讲题摘要，并由现有 `prepare` 入口生成单个可离线阅读的 `review.html`。覆盖当天实际学习的定义、关键条件、成立的二级结论及其边界，包括正确题暴露的知识内容。相同机制可合并，目录按科目和机制组织，动态机制用有意义的点击、步进或对照。日终用阅读版，不开启问答。

## 睡前资料：独立核心知识卡（2026-11-07）

每张只讲一个具体知识点，直接给出简短核心结论、必要条件和对应机制图。卡片脱离原题、前卡及历史对话仍能独立理解；必需的对象、符号、单位、状态或例子直接给齐。结论与条件以一两句能说清为宜，确有必要才补解释，不用长篇总述包围知识点。数量按当天真实内容决定，不固定卡数、不凑数。

- 正文直接讲知识：例如“ACK已经表示下一期待，不能再次加一”。不写“你此前如何作答、哪些已会或未掌握、提示后有什么变化”，不加学习画像、表现评价、估分、逐题表现清单或大段整体总结；这些证据只保留在原记录及备课依据中。
- 条件说明结论何时可用、对象和单位是什么、边界如何检查。它不是对用户掌握程度的评价。内容依据本次真实学习原件、已核题源/教材和当前有效概况；复用当前会话已经核过的同版资料，不为改展示形式重复入库或全库扫描。
- 图解要呈现实际机制：页表画出记录位置、格内内容与目标页；缓冲画各资源的占用和末块收尾；协议画AS边界、消息方向和报文封装。只有框名、阶段名称、装饰箭头或点击后出现泛化说明，不算完成图解。时序、比例、方向与文字结论必须一致。
- 优先清晰的结构图、时间线、字段布局、状态切换或机制对照；需要时点击具体对象/步骤以突出关系或切换状态。文字保留当前结论和必要条件，不把唯一解释藏在点击后。沿用原题有意义的结构；另设例子标“机制示例”，不冒充原题或新的作答。公式保持原生数学或文档文字排版，不转成位图。
- 交互阅读版一次聚焦一张卡，可按目录跳转，支持逐卡备注、复制核心内容和导出备注。说明备注实际保存位置；本地保存要验证重新打开后仍在，不能只放一个不会保存的输入框。PDF等静态版本保留同样的知识结论和图解，留出可直接批注的位置。按用户需要选择格式，不把“换成网页”当作内容改写。
- 完成前核对结论与条件、图中文字和方向、备注保存/导出及实际交付文件；只对发现的问题作相称修复。卡片不出现未获授权的后题答案、兄弟问答案或隐藏解答数据。制作、打开、点击和备注不自动写入作答、评分、FSRS或掌握度。

知识卡直接交付为阅读资料。全天版使用专用阅读计划；`cs408-evening-plan-v1` 和问答开始流程只用于实际问答。当前阅读文件留本机热展示目录，制作脚本、检查材料和历史版本按本科T9检查、登记与读回约定保存；已有原件保留。用户明确只看某一点时只做对应卡，不附整场评价。

## 问答备题

由当前本地会话完成完整教师稿。读取项目 `schema/evening-review-408-v1.md` 的问答 plan 合同；保留已由用户确认的实际学习日期、来源和按题作答方式。

- 通常3–5个主问题、最多5个，重点少就少出；思考、回答、反馈和收尾总计约10–15分钟，900秒为上限，不凑满时长。默认无reserve，无逐题强制复述或额外迁移题。单题只检查一个核心断点，不把一套小问塞成一道。
- 每题自带可独立作答的对象、状态、条件、参数、单位和目标；树/图/地址布局/访问序列等必要输入直接给全。不用“看原题、上一题、刚才那个”代替上下文。依赖前问时直接提供已核验必要结果作为已知输入；当前待答结论仍保护，其他题的答案不能成为前置。删去所有其他题，本题仍能作答。
- 默认检查机制、条件、方向、边界、单位或一步状态变化，尽量免计算。无计算断点时给出不需要检查的中间结果；只有真实原话/草稿证实算错某一步，才将该步单独拎出重算，不重做完整大题。微型机制场景标为复盘自编，不冒称真题或用户经历。
- 从当天真实首答、提示后修复、只认可解释和未验证边界选重点；不推测错因、不将提示后完成写成独立掌握。全部Capture逐项注明入题/合并/暂缓/有证据无需单问，覆盖核对齐全不等于本次检查齐全。未检查内容如实保留，不为轻量虚构掌握。

2026-10-07高频优先：只在当天真实学习范围内，按同版frequency-priority.json先检查有真实断点或未验证边界的高频点；这些候选已安排，或有当天清楚证据无需单问后，才补中频、低频。不能因时间不够把高频暂缓却问低频，不从全库补非当天高频。D0知识点仍可复盘，精确旧题不能重出近14天已做或已展示的题；使用明确标注的独立新机制场景，核对它没有照搬已做题面。全部Capture保留coverage。新输入的plan增加私有selection_audit，逐点记录安排/有证据无需单问/暂缓及新场景来源，具体字段见晚间合同；题目原字段不增加，学生材料不展示核验与答案。

## 问答的本地编写与准入

1. 在项目目录运行 `python3 scripts/runtime_paths_408.py --run evening_review_408.py local-context --date YYYY-MM-DD`。读取该日封存原件、本机增强收尾凭据和原生讲题同版个人摘要，返回 `READY_FOR_LOCAL_AUTHORING`、内部输入文件和 `handoff_sha256`。缺少增强收尾时列出具体 Capture 和阶段。已有正式入库授权就本地续办；只要求晚间复盘时保留原范围，不静默新增正式学习事实。本地归档、质量索引或读回缺失时沿已有回执补齐。COMMITTED_QUALITY_PENDING 按待补层报告。
2. 当前会话直接读内部 ZIP 的 handoff.json、personal-context.json、frequency-priority.json（存在时）、对应的原始讨论和增强成稿。按合同编写本地 plan.json，绑定同版及同一日期的 SHA，逐条交代当天 Capture 去向、优先顺序与未单问的理由。把题面和私有参考回答分开；只写确有证据的学习表现。按 T9 检查、登记约定保存计划。
3. 运行 `python3 scripts/runtime_paths_408.py --run evening_review_408.py prepare --input <内部输入绝对路径> --plan <本地plan.json>`，读回 `PREPARED_NOT_STARTED` 与 `start_study_path`。用户要求开始才进入下一段。备题和提交在当前会话连续办理，用户无需中转文件。
4. 仅当用户明确要求外部交接才用 `export --web-handoff`。已有回包按来源和原输入直接本地 prepare；部分成稿也由当前会话续办。

## 问答开始与收尾

用户要求开始后，一次只展示一个core问题并等待真实回答；不先展示纠错总结、教师答案或后题内容。答清楚就简短反馈并下一题；有歧义才问一个定点追问，重新给足当前条件。卡住时给最小提示，连续两次仍无进展或用户明确要讲解时，直接讲清当前题，区分提示/讲解暴露与独立作答。实质讲解沿question-worker合同：同轮以正文连续讲清当前获准的步骤与因果，配对应可点击图解辅助抽象关系，主线不藏在点击里；提示轮仅解释本轮提示，直接讲解才展开本问全解。图解只服务当前题，不为画图延长备课或泄露答案；单一事实、简短确认、导航和用户明确纯文字请求保留例外。

只有真实开始才记录开始时间；不把prepare、打开题包或等待工具算作学习。约15分钟或用户要求停止时按真实完成范围收尾，不强迫做完。未问/未答/听过解释均不写成独立掌握。现有active/paused会话从当前进度继续，不重开。

此入口不建Capture、不调FSRS、不改原题日期/错误次数，不自动提交个人摘要；用户要求保存整场或正式更新时才按 `schema/concept_review_v1.md` 的真实证据合同执行。只修改Skill或提示词不授权写学习事实。

历史v1问答、v2阅读包与回执保留原样。用户明确要阅读旧HTML就直接打开；用户要求用旧材料开始问答时，依其真实来源按本版规则准备少量问题，不把已经展示的解释当作未提示测试。网页工具失败保留已完成内容、原文件和具体缺口，只续接缺项，不声称完整READY。
