## 日终原始总包

用户明确要求结束当日408学习并打包转交网页时，先让当前原事务完成必要封存；结束未解题用hold，不再展示新题。然后调用：

`python3 scripts/runtime_paths_408.py --run export_capture_day_408.py --date <真实上海日期> --web-handoff`

导出当日全部已封Capture及其补充版本，原件和真实身份不变；不要求先正式入库或把记录发布成已接受历史。未封展示/缺原件明确报告，不能删掉题凑成全量ZIP。原始总包给网页408正式增强业务，下载和导出不是学习完成或正式入库。

新导出冻结一个真实Study Library版本，并附`TEACHING_ALIGNMENT_REQUIREMENTS.json`、相关旧教案/路线版本、原考纲范围和`408-portable-question-teaching-v1.md`。每片重算自己的精确Capture集合与输入绑定并在本机登记；网页不能通过省略教案文件绕过新输入要求。已存在旧ZIP保留原合同，不为升级重封原Capture；若新快照缺所需版本字段，先补发布/取数层，不拿当前热对象冒充旧快照。

网页固定资料包括工作流/合同和用户上传的真题、考纲等客观来源；MCP负责同版真实个人历史及现有教案。每批启动词要求同时交个人概况/父小点计划及`portable_question_teaching_updates.json`，明确retain/revise/source_limited，并核原题实际图形。完整流程以`schema/408-web-enhancement-authoring.md`为准，本地审核后才正式生效。准备好可直接上传的项目文件和完整替换说明，实际网页配置仍按用户手动上传流程，不把本地文件更新写成线上已保存。

2026-09-27起总包默认直接写到T9数据盘 `/Volumes/T9-Data/01_408/408网页中转/日终加强输入/<日期>/`（经T9哨兵核对），分片默认跟随原包位置；每批按科目/知识点自建的分片出包目录也建在 `日终加强输入/<日期>-enhancement-<N>/`，交给用户的总包和提示词链接一律用T9路径，本机不再留副本。T9未挂载或UUID不符时保留已封存证据，停止本批冷资料导出；挂载恢复后续办，不静默回落本机。

大批原始Capture导出超过40项时，export_capture_day_408自动返回分片和配套启动词，默认每片约30项，大批通常5—6片；每个Capture的完整对话、附件与补充链不能拆开。`partition_status=PENDING`表示原始总包已保存、只需恢复拆分，不重新封Capture。也可调用 `scripts/split_web_input_408.py --kind enhancement --zip <原始总包> --parts <数量>`。导出时一次固定正式source_commit，全部网页会话只读同版资料；一会话一包。小批保持原单包入口，不启动网页或模型。

用户明确指定看板待处理数量或精确集合时，先冻结真实Capture ID并集，核对跨日构成；关闭当前未答题新产生的Capture单独保留，不混入原指定集合。按Capture真实study_date先分组，再按知识点和体量分片，每片保持单日；不能用父包日期替换原学习日期。MCP来源优先沿用fetch的source_ref，输入manifest在实际根目录，不猜不存在的return-template/manifest.json。

不同片涉及同一知识点时，网页各交真实证据及本片候选成稿，本地收齐后合成该点唯一最终概况/短摘要。全部正式决定先按父Capture并集核对并合成一个原生增强包，再串行正式写入、发布一次；晨间备课按用户请求本地继续；不可并发apply各片，也不可后片覆盖前片摘要。分片身份放partition.json并列入files，正式manifest不添加未支持字段。

交给网页的启动说明必须要求逐项保全、失败后继续其他独立项，最终始终交实际成功文件、EXECUTION_REPORT.md和web_execution_report.json；明确失败调用的真实工具名/参数/原始错误。尾部失败不清零前面成果，真实零成功才报告零。PARTIAL加强包回本地由enhancement-intake保全、补全失败部分和正式写入，再维护真实读取问题并导出下一轮晨间资料。不要让用户因网页局部失败重新打包或重做已成功学习。

## 派生资料不改变输入证据

新包沿原模板携带当前 API 使用与证据边界说明。按需提取稿、疑义页提示和语义候选只作带来源的辅助，不能替换完整 Capture、原图、真实对话或固定快照，也不改变包身份、日期、答案保护或本地串行审核。打包入口保持确定性，不为打包等待模型；若原件确需另行预处理，沿现有资料入口处理并保留原件，不能把上传附件的沙盒路径传成 MCP 已发布路径。旧 ZIP、已冻结队列和成功正式事务不为同步说明重封或重放。


## 已封存精确集合导出

导出已封存的精确集合可在原入口重复传`--capture-id <CAP>`。入口核对每项原始日期、完整原件与消息边界，并用`EXPORT_SCOPE.json`列明集合外仍未封存的展示；不关闭或重排active/paused，不把未答题记为完成。默认整日导出仍会因未封存展示阻塞。用户限定最多5片时按真实日期和科目分组后调用原`split_captures(..., capture_groups=...)`，不得让自动默认分片超过用户限额。
