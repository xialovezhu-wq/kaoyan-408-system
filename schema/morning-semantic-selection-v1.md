Morning semantic selection v1

Python freezes canonical due actions, exact ledger outcomes, formal-node and review-unit
bindings, original-question assets, relations, knowledge-point evidence and source hashes.
It never ranks the final five semantically. The root Sol plans native read-only Luna Max Fast
shards from the frozen candidate count, natural evidence domains, independent splittability and
expected concurrent benefit. The count is not fixed at one, three or any other topology, and
shards are never created merely to fill available slots. With no useful delegation benefit, the
plan uses `delegation_mode=root_direct`, contains zero shards and deterministically carries every
eligible frozen candidate forward; it may not silently prefilter that eligible set. An indivisible
delegated domain may use one shard, while multiple independent domains may use multiple shards.
When Luna is used, `delegation_mode=native_luna_shards` contains at least one shard and no more
shards than the deterministic safety bound derived from the unique frozen candidates. The legacy
single-candidate-set entry remains readable for old artifacts, but new dynamically planned
production work uses `validate-luna-shards` and `luna-morning-candidate-shards-v1.json`.

Every shard has one unique `shard_id`, a non-empty natural `evidence_domain`, a disjoint list of
authorized frozen candidate IDs and a deterministic scope hash over the snapshot SHA, shard ID
and the exact authorized candidate bytes. Its native runtime receipt binds the same snapshot,
shard and scope and confirms `gpt-5.6-luna`, reasoning `max`, Fast service and zero formal writes.
The Luna advisory carries only candidate IDs, bounded reasons, counterevidence and semantic
scores. Python materializes all dates, IDs, knowledge points, evidence references, outcome rows,
surface modes and exact-display exposure rows from the frozen snapshot; Luna cannot rewrite
those static fields.

Machine source identity is also deterministic. An action `source_id` is copied only when it
matches the exact `CurrentQuestionContext v1` stable-ID grammar. A human title such as
`2014统考第25题` is stored separately as `source_label`; it is never used as the transaction ID.
When the raw action source is not consumer-compatible, Python may set the machine `source_id` to
the formal node only if the frozen action resolves to exactly one canonical, hash-bound
`formal_node_id`. Such a row records `source_id_provenance=formal_node_fallback`. A compatible
raw machine ID records `source_id_provenance=action_source_id`. Missing, noncanonical or multiple
formal-node fallbacks are `needs_user` with
`source_id_not_current_question_compatible` and
`source_id_formal_node_fallback_not_unique`; they cannot reach Sol selection or queue publication.

Bundle validation fails closed when `root_direct` contains any native shard, when
`native_luna_shards` is empty or includes an empty/out-of-bound shard, or on duplicate shard ID,
overlapping authorization, unknown or repeated candidate ID, out-of-scope advisory, snapshot,
plan, scope or runtime-receipt drift, and any nonzero formal write count. The validated fan-in is
one content-addressed `validated_luna_morning_candidate_set_v1` object with root-direct or
per-shard candidate provenance. The root Sol reopens the same snapshot and validated bytes,
resolves cross-shard duplication and conflicts, and is the only final selector. It may choose at
most five distinct nodes and primary knowledge points; fewer are allowed and padding is forbidden.

The original-question gate is independent from scheduling. Learner-visible display truth comes
from content-addressed private `display_published` receipts. Every accepted receipt must bind the
same session, review date, item, immutable prepared-pack manifest, main surface and question
asset. Historical receipts without their own timestamp inherit the immutable session
`review_date`; filesystem mtime is never evidence. The snapshot stores the normalized recent
display set and its fingerprint, and freshness recomputes that fingerprint before queue
publication.

An exact question-asset display gap smaller than seven days requires a derived variant whether
the item was answered, left unanswered, answered with a hint, or answered incorrectly. A gap of
exactly seven days or more permits the original. The latest valid no-prompt, no-hint canonical
outcome remains semantic ranking evidence only; it no longer authorizes reusing an original
surface. Missing identity, stable asset, or answer-isolated details evidence is `needs_user` and
cannot be selected.

Prepared-pack publication and cold audit independently apply the same seven-day gate to the
normalized main-question identity. An image question is identified first by its asset SHA-256.
A text-only question is identified by normalized stem plus A/B/C/D option text, explicitly
excluding `item_id` and response instruction. Exact repeats are rejected for both original and
derived items. A different asset or genuinely different stem/options for the same knowledge
point is allowed. Guided and repair surfaces remain same-item teaching branches and are not
treated as separate scheduled questions by this gate. Publication excludes no exposure. A cold
audit excludes only display receipts already bound to the exact prepared-pack manifest being
audited, so a used pack can still prove its own integrity; the same surface from every other
recent pack remains a hard failure.

Original surfaces bind one stable details-vault question asset and repeat that same original in
guided and repair roles. A model-authored variant never carries `item_kind=original_question`.
All selection objects and queues are content-addressed, answer-safe outside private evaluators,
and keep learner/formal write counts at zero. Dates, IDs, hashes, eligibility, the seven-day exact
exposure gate, idempotency and structural validation remain deterministic. Luna shards are
read-only advisory producers; the queue, prepared pack, session, receipts and review ledger stay
under their existing serialized single writers. Every new queue item carries `source_id`,
`source_label`, and `source_id_provenance`; prepared-pack publication must reject a machine source
that the current-question consumer cannot validate.
