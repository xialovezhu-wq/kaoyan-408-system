# 408 复习单元与晨间全覆盖协议 v2

本协议定义复习单元重构、到期判定、晨间执行和结果记录。研究依据见 [[wiki/source_summaries/408晨间复盘学习科学文献综述|408 晨间复盘学习科学文献综述]]。

## 一、三层事实

1. **正式错题层**：`节点总表.md`、安全节点卡、关系边。它说明每道错题实际考什么，不由晨间复盘改写。
2. **正式复习单元层**：`复习单元总表.md` 与节点覆盖映射。它定义长期调度对象；掌握度 0–5 只能来自用户。
3. **晨间派生事件层**：StudyVault 安全队列与结果事件。它记录首答、置信度、反应时、反馈和修复再提取，不自动冒充正式掌握度。

## 二、复习单元粒度

一个复习单元必须能用一次闭卷提取检验一个稳定的“可生成答案”目标：

- 第一动作；或
- 一条机制 / 状态 / 数据流；或
- 一组必须同时辨析的相邻概念；或
- 一类计算模型的变量语义与边界。

出现以下任一情况应拆分：

- 需要三个以上相互独立的第一动作。
- 一个子点答错不代表另一个子点不稳。
- 同一单元同时跨越无直接依赖的两个模块。
- 完成闭卷回答通常需要多道互不相干的问题。

出现以下情况可合并：

- 多道错题共享同一识别信号、第一动作和失败模式。
- 相邻知识点必须通过对比才能稳定判别。
- 关系语义审计已经确认同一题型模板或上下游机制链。

## 三、逐题覆盖硬门禁

每个正式节点必须在 `复习单元节点映射.md` 中恰好有一个主复习单元，可有 0–2 个次复习单元。

映射至少记录：

- 正式节点 ID。
- 实际考点。
- 主复习单元 ID。
- 次复习单元 ID。
- 覆盖方式：核心机制 / 第一动作 / 边界辨析 / 迁移 / 原题轮换。
- 复核状态：`reviewed` / `needs_user`。
- 原题轨资格：按最近复做日期动态判断，不在映射表中写死答案或题干。

发布门禁：

```text
mapped_formal_nodes == formal_nodes
duplicate_primary_mapping == 0
missing_review_unit_endpoint == 0
protected_content_findings == 0
```

## 四、复习单元卡

每个正式复习单元应有安全卡，至少包含：

- 单元 ID、科目、模块、机制名称。
- 覆盖正式节点列表。
- 核心保持问题。
- 第一动作问题。
- 边界 / 易混辨析问题。
- 迁移问题或迁移生成规则。
- 折叠的派生自查口径。
- 首答达标标准。
- 需要拆分或待用户补证据的事项。

问题区不得先泄露机制结论；自查内容必须放在折叠 callout，并明确是“派生自查口径”，不是原题标准答案。

`复习单元总表.md` 使用 v2 字段：`调度状态`、`覆盖节点`、`闭卷问题` 与 `派生自查口径` 分列保存。不得再把答案式讲解混在“复习方式”里。

## 五、到期集合

晨间集合由以下来源合并并按 `RU_*` 去重：

- `下次复习日期 <= 今天` 的正式复习单元。
- 前一晚 D0 中明确不稳、需要 D1 的安全派生单元。
- 上次队列仍 open 的未达标单元。
- 重构后尚无可信日期的 active 单元（`uncalibrated_baseline_due`、`recalibration_required_after_split_or_merge`、`history_due_recalibration`）。

禁止 `top-N`、`max-items` 或时间预算截断。生成器必须验证：

```text
due_count == included_count
skipped_count == 0
```

`blocked_needs_user` 不进入可评分分母，但必须单列显示，直至补齐证据。重构产生的基线积压不得虚构未来日期分散掉：它整体保持 due/open；可以跨批次恢复，但未完成前不能声称本轮关闭。

## 六、冷启动间隔与自适应

`D1 / D3 / D7 / D14 / D30 / D60 / D90` 只是缺少个体历史时的冷启动锚点，不是普适最优曲线。

下一次建议至少参考：

- 上次无提示独立成功日期。
- 实际间隔。
- 首答正确性。
- 置信度和相对题型反应时。
- 是否使用提示。
- 历史失败 / 复发次数。
- 保持状态与迁移状态。
- 目标考试 / 保持期限。

不再自动使用固定 `×2.5 / ×2 / ×0.5` 倍率。

## 七、晨间执行算法

### 首答轮

每个到期单元都先闭卷回答。首答枚举：

- `independent_correct`
- `fragile_correct`
- `partial`
- `wrong`
- `blank`

同时记录 `confidence=low|medium|high`、反应时、提示使用和首个断裂环节。

### 反馈与修复轮

- `independent_correct` 且不迟缓：本次达到保持标准；高价值单元可加迁移探针。
- `fragile_correct`：短反馈核验，隔开后换线索再问。
- `partial`：定位首个断点，逐级提示，稍后重提取。
- `wrong`：区分普通错误与高置信错误信念，纠正后换情境重提取。
- `blank`：短暂尝试后给提示，不无限空想；随后闭卷重提取。

每个到期单元至少一次无提示独立正确，才完成本次 relearning。看懂反馈不算完成。同日修复成功不冒充下一次跨日成功。

## 八、全覆盖指标

```text
queue_coverage = first_attempt_count / due_count
criterion_coverage = independent_success_count / due_count
```

- `queue_coverage` 必须 100%。
- `criterion_coverage` 目标 100%。
- `carried_over` 表示队列保持 open，不算 session closed。
- 批次和休息只保存断点，不改变分母。

## 九、批次

默认 `batch_size=10` 只是可调工程参数，不是文献常数。

- 批次按风险和机制组织。
- 真正易混概念可局部交错。
- 不随机混排无关四科来制造表面交错。
- 每批结束保存结果；需要时休息，再继续同一队列。

## 十、保持与迁移分开

- `retention_status`：能否直接提取机制、第一动作和边界。
- `transfer_status`：能否在新情境中选择机制或完成近迁移。

只会背定义但不会判型，不能标为整体掌握。D14 之后或高价值单元应周期性加入迁移问法。

## 十一、7 天双轨保护

- 近 7 天题：只走知识机制轨，不输出具体历史题。
- 原题复做轨：必须通过 7 天外硬筛选，并输出安全定位；没有可靠候选时不凑数。
- `原题复做轨总表.md` 必须一题一行保留全部正式节点。机制单元可以把同机制题合并，但原题轨不得合并。
- 重构冷启动时，原题轨先标为 `awaiting_primary_baseline`；主机制取得一次无提示独立成功、且满足 7 天保护后，才转成可到期原题项。这个先决条件只决定何时到期，不允许从已经到期的原题集合中删项。
- `blocked_needs_user` 必须保留定位与待补事项，不进入可评分分母，也不得伪造题目内容。

原题轨状态机：

```text
awaiting_primary_baseline
  -> active_due          # 主机制独立成功，且已满 7 天或日期未记录
  -> active_scheduled    # 主机制独立成功，但仍在 7 天保护期
  -> active_due          # 到达最早允许日
```

正式转换由 `scripts/activate_original_question_tracks.py` 完成。它必须回读同一份 open 队列中的 `independent_correct` 证据；符合资格的原题立即追加到同一 open 队列，不能等到次日，也不能修改掌握度。

知识机制轨的全覆盖不等于每天重复原题。

## 十二、正式写入边界

晨间派生结果不得自动换算为正式掌握度：

- 掌握度只能在用户明确给出 0–5 分后更新；任何正式回流流程都不能替用户打分。
- 上次复习日期、当前间隔和下次复习日期，必须同时存在真实完成事件与授权的正式回流，才可更新。
- 原题轨激活可以依据可核验的“主机制无提示独立成功”事件，但它不等于掌握度评分。

正式节点、关系边、题图详情和 `复盘输出/` 不属于本协议的写入范围。
